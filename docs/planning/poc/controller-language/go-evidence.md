# Go candidate evidence: SSH-first controller slice

Snapshot date: 2026-10-07. Research only: no install, build, SSH connection,
Keychain access, runtime test, or language selection. Package versions/dates are
what the official pages showed in this snapshot; refresh before a PoC.

| Dimension | Documented evidence | Unknown / implication |
|---|---|---|
| SSH/auth: `golang.org/x/crypto/ssh` v0.57.0 | [Pinned package docs](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/ssh) report v0.57.0, published 2026-09-08, BSD-3-Clause. `ClientConfig` carries `Auth`; [pinned ssh/agent](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/ssh/agent) documents agent client and `$SSH_AUTH_SOCK`; public-key and password auth APIs are present. The exact [tagged go.mod](https://github.com/golang/crypto/blob/v0.57.0/go.mod) requires Go 1.26.0. | Library hooks do not decide which credentials resolve for a target, prompt/expiry behavior, algorithm policy, or lifecycle. The environment's installed Go 1.20.1 (reported by root) does not establish that current dependency builds. No install/build was attempted. |
| Host trust | [Pinned ssh.ClientConfig.HostKeyCallback](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/ssh#ClientConfig) is required; callback can accept/reject the host key. [`knownhosts.New`](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/ssh/knownhosts#New) parses OpenSSH known_hosts files. Its `KeyError` distinguishes unknown from mismatching keys; interactive applications may offer a prompt. | This is an API hook and file parser, not ADR-003's local first-use ceremony. Fingerprint display/independent verification, explicit trust recording, changed-key refusal without replacement, endpoint rebinding and separate host-trust state need caller policy and tests. Never use `InsecureIgnoreHostKey` in production. |
| Context, timeout and cancel | [`net.Dialer.DialContext`](https://pkg.go.dev/net#Dialer.DialContext) cancels dialing, but docs say context expiry after a successful connection does not affect that connection. [`net.Conn.SetDeadline`](https://pkg.go.dev/net#Conn) can bound I/O/SSH handshake. [`ssh.Session.Signal`](https://pkg.go.dev/golang.org/x/crypto@v0.57.0/ssh#Session.Signal) requests a remote POSIX signal; `Session.Close` closes the channel. | Caller must compose deadlines and cancellation across dial, handshake, auth, command and output. A signal is a request and server support/effect is unverified; closing a channel or local context does not prove remote completion/cancellation. After possible dispatch, retain ownership and reconcile the original operation per ADR-003. |
| macOS credential library: `github.com/zalando/go-keyring` v0.2.8 | [Pinned Go package page](https://pkg.go.dev/github.com/zalando/go-keyring@v0.2.8) reports v0.2.8, published 2026-03-23, MIT. It exposes Set/Get/Delete; its [upstream README](https://github.com/zalando/go-keyring) says macOS uses the `security` command to access Keychain. The tagged [Darwin implementation](https://github.com/zalando/go-keyring/blob/v0.2.8/keyring_darwin.go) calls `/usr/bin/security`; Set uses `security -i` and sends an `add-generic-password -U` command with base64-encoded secret on stdin, not argv, updating a matching item. Get uses `CombinedOutput`, whose output contains the secret. | The backend returns `ErrNotFound` only for “could not be found”; other failures remain generic subprocess errors (no typed locked-store classification). Review output sanitization, cancellation, output limits and ACL/prompt UX, plus secret recovery/rotation, backup/export and signed/sandboxed-app fit; none was tested. The library does not satisfy ADR-005/006 store or backup review. |
| Strict JSON | Stable [`encoding/json` v1](https://pkg.go.dev/encoding/json) permits duplicate object names; later occurrences replace or merge according to destination type. `Decoder.DisallowUnknownFields` rejects unknown object fields when decoding into a struct. [Go 1.26.0 `encoding/json/v2`](https://pkg.go.dev/encoding/json/v2@go1.26.0) is experimental, requires `GOEXPERIMENT=jsonv2`, and is not covered by the Go 1 compatibility promise. It rejects duplicate names by default; unknown members are ignored by default, with `RejectUnknownMembers` opt-in and `AllowDuplicateNames` disabling duplicate rejection. | Duplicate rejection is not a default stable v1 guarantee. V1's unknown-field switch applies to structs, not arbitrary nested `any` maps; exact number/range policy, canonical bytes, extensions and serialization compatibility need explicit contract tests. V2 integration and behavior against all EasyNet contract cases remain unverified. |
| macOS ARM64 toolchain | Go supports `GOOS=darwin GOARCH=arm64` (macOS Apple Silicon since Go 1.16; see [Go 1.16 notes](https://go.dev/doc/go1.16) and [platform build targets](https://go.dev/doc/install/source)). The official [downloads page](https://go.dev/dl/) lists darwin-arm64 archives/installers. Go 1.26 requires macOS 12+ per [minimum requirements](https://go.dev/wiki/MinimumRequirements). | Cross-compilation support is not a packaged app acceptance. Signing/notarization, update/installer format, universal amd64+arm64 artifact, Keychain authorization behavior, reproducibility and distribution checks were not tested. Current Go docs and x/crypto v0.57.0 require toolchain alignment; local Go 1.20.1 is insufficient evidence. |
| License, maintenance, dependency closure | x/crypto is BSD-3-Clause; go-keyring is MIT. Both have tagged versions and dated publication signals above. Go's official downloads page provides checksums for published platform archives. | License inventory for the full selected module graph and packaged toolchain is outstanding. Release activity does not guarantee support. Binary size, package size, cost, and supported app deployment matrix are unknown; no measurements were taken. |

Positive evidence: Go has SSH auth/host-key callback and known_hosts APIs, cancellable
dialing/deadlines, a macOS Keychain wrapper, a documented duplicate-key strict mode
in JSON v2, and a darwin/arm64 target. Negative evidence: those building blocks do
not provide the shared authorization/trust/operation policy or remote cancellation
proof required by ADR-001/003. This evidence records APIs, not successful behavior.
