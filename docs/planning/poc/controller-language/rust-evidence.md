# Rust candidate evidence: SSH-first controller slice

Snapshot date: 2026-10-07. Research only; no install, build, SSH connection,
Keychain access, runtime test, or language selection was performed. Versions
below are the versions shown by the linked official crate/project pages at the
snapshot; recheck immediately before a PoC because these pages move.

| Dimension | Documented evidence | Unknown / implication |
|---|---|---|
| SSH client/auth: `ssh2` 0.9.6 | [API](https://docs.rs/ssh2/0.9.6/ssh2/struct.Session.html) exposes password, keyboard-interactive, key-file, and agent authentication; `agent()` gives more identity control than the first-key helper. It is safe bindings over libssh2 and builds or links libssh2. [Upstream README](https://github.com/rust-lang/ssh2-rs) says OpenSSL is needed and supports vendored OpenSSL. | API presence does not show policy integration, agent socket discovery, cancellation behavior, or supported key formats in this app. Native dependency/linking and supply-chain maintenance need a pinned build experiment. The [tag page](https://github.com/rust-lang/ssh2-rs/tags) dates 0.9.6 to 2026-06-30; the [GitHub Releases page](https://github.com/rust-lang/ssh2-rs/releases) has no release entries. Release/tag cadence is a signal, not a maintenance guarantee. |
| Host trust: `ssh2` 0.9.6 | [KnownHosts API](https://docs.rs/ssh2/0.9.6/ssh2/struct.KnownHosts.html) reads/writes OpenSSH known-host files and checks host/key (including non-default ports), returning Match, NotFound, Mismatch, or Failure. | The docs example accepts and writes NotFound, which is not ADR-003's explicit local confirmation ceremony. UI display, independent fingerprint verification, refusing changed keys without replacing old trust, storage separation, and trust migration are caller responsibilities; no accepted policy implementation is documented. |
| SSH client/auth + trust: Russh | The [client Handler API](https://docs.rs/russh/0.63.3/russh/client/trait.Handler.html) calls `check_server_key`; its default rejects keys, and an override decides trust. [Client module](https://docs.rs/russh/0.63.3/russh/client/) documents async client handling. The [v0.63.3 release](https://github.com/Eugeny/russh/releases/tag/v0.63.3), 2026-09-09, fixed inactivity timeout during stalled writes. API notes here are from 0.63.3 research; the [v0.64.1 release](https://github.com/Eugeny/russh/releases/tag/v0.64.1), 2026-10-05, includes a security fix. The official [GHSA-4wc5-f2rc-q74m advisory](https://github.com/Eugeny/russh/security/advisories/GHSA-4wc5-f2rc-q74m) affects versions <=0.64.0 and is patched in 0.64.1. It concerns unbounded memory/task growth in the SSH agent protocol server, reachable by a local agent peer or a remote SSH server when agent forwarding is enabled. This is a scoped agent-server issue, not a blanket SSH-client finding. | Callback gives a hook, not the ADR-003 ceremony or known-host persistence. Key/agent auth support, retry policy, socket/command deadlines, UI cancellation wiring, and behavior after local task cancellation need a bounded PoC. Dropping/canceling observation cannot be treated as remote cancellation or release of operation ownership. Any PoC must review the fixed release/advisory and keep agent forwarding disabled by default per ADR-003. |
| Timeouts and cancel | `ssh2::Session::set_timeout` bounds blocking libssh2 calls; default/zero is unlimited ([API](https://docs.rs/ssh2/0.9.6/ssh2/struct.Session.html)). Russh release history documents an inactivity timeout fix and API has async client callbacks. | Timeout is not cancellation or proof of remote outcome. Neither source establishes that stopping the local task stops the remote process; after dispatch classify outcome as unknown and reconcile under ADR-003. Need tests for connect, auth, command, output, and cancellation at each phase. |
| Credential store: keyring 4.2.0 | [v1 API docs](https://docs.rs/keyring/4.2.0/keyring/v1/) identify macOS Keychain Services and expose set/get/delete; [`Entry` docs](https://docs.rs/keyring/4.2.0/keyring/v1/struct.Entry.html) expose store initialization status and CRUD. The crate page dates 4.2.0 to 2026-08-29. | API specifies a simple named secret store. Direct Entry creation, access prompts/ACL behavior, locked/unavailable Keychain UX, secret overwrite/recovery, rotation/revocation, backup/export and ergonomic use from a sandboxed/signed app are unverified. `set_*` creates a credential or updates the matching existing one; this is not safe implicit rotation. ADR-005/006 still govern store/backup decisions. |
| Strict serialization | [serde_json 1.0.151](https://docs.rs/serde_json/1.0.151/serde_json/) supports typed Deserialize and generic `Value`; its [Map API](https://docs.rs/serde_json/1.0.151/serde_json/struct.Map.html) says insert replaces an existing key. [Serde de::Error](https://docs.rs/serde/1.0.228/serde/de/trait.Error.html) defines `duplicate_field` for typed structs. | A strict production reader still needs explicit unknown-field, duplicate-key (including nested arbitrary values), numeric/range, canonicalization and serialization rules. Generic `Value` behavior and custom deserializers need direct tests; do not assume typed duplicate-field handling rejects every duplicate JSON object key. |
| macOS ARM64 | Rust's [Apple Darwin target page](https://doc.rust-lang.org/rustc/platform-support/apple-darwin.html) lists `aarch64-apple-darwin` as Tier 1, macOS 11+; target is distributed by rustup. The page notes C cross-compilation may require Xcode/SDK. | Rust target support does not certify a packaged app. Signing/notarization, updater, installer format, universal/x86 support, keychain entitlements/prompts, OpenSSL/libssh2 linking, reproducible release CI and actual arm64 artifact are untested. |
| License, maintenance, cost/size | ssh2-rs upstream declares Apache-2.0 OR MIT. Russh upstream declares Apache-2.0. Keyring upstream declares Apache-2.0/MIT and names an active maintainer; its 4.2.0 release was 2026-08-29. Official Rust target support is maintained by named target maintainers. | Full transitive license/SBOM review is outstanding. No credible package price or shipped binary-size evidence was found; treat both as unknown. Release activity is a dated signal, not a support guarantee. |

Candidate comparison is intentionally bounded: `ssh2` offers a synchronous libssh2
wrapper and known-host collection; Russh offers async client hooks and an
explicit reject-by-default host-key callback. Neither library supplies EasyNet's
shared authorization, trust ceremony, immutable operation ownership, receipt
validation, or remote cancellation/reconciliation. This evidence establishes
documented APIs only, not security suitability or runtime success.
