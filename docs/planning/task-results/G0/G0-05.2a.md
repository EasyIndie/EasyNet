## Source behavior

Explicit seeding accepts only an existing empty owned root; open never seeds,
reads, repairs or migrates. The descriptor-rooted store guards root/file owner,
exact permissions, file type and link count; rejects unsafe paths before access;
serializes methods and Close; and holds a stable lock inode. Lock acquisition is
nonblocking with a two-second deadline and ten-millisecond poll; held/named inode
and root guards run again **after successful flock**, before state access.

Load/Snapshot read at most 16 KiB plus one byte and return only whole validated
copies or fixed error codes with a zero snapshot. Migration inspection validates
v0 without increment. Commit/migration CAS uses the shared validators and canonical
codec under exclusive flock, creates a private exclusive stage, checks full write,
fsyncs/closes it, renames atomically, syncs the directory, then acknowledges.
Prepublication faults yield IO; rename invocation and subsequent ambiguous failures
yield CommitUnknown, with no replay. Private before/after publication and before
acknowledgment hooks exist only for this owned harness.

The process harness launches only the current test executable with the exact child
helper selector, fixed scenarios, fake exact bindings and minimal LANG/PATH/root/
scenario environment. Owned event/control pipes use bounded fixed acknowledgments;
stdout/stderr are drained while retaining at most 4096 bytes each. Every child has
a three-second deadline and one-second WaitDelay, and is explicitly waited or
killed/reaped before fixture cleanup. No side-effecting init or TestMain exists.

Boundary crash trials release the beforePublish pipe barrier and actually race
owned-child Kill/Wait against publication/ack, distinct from deterministic hook
kills. Harness-only recovery records owned staging names after reaping, removes
only those names, requires a complete old/new snapshot, then freezes physical
baseline. Each purity check performs three repetitions (Load+Snapshot for v1;
InspectMigration for old v0), comparing names, bytes, modes and generation. Atime
is deliberately not asserted. Crash trials report actual schema/generation and
recorded artifacts in the successful actual log.

Source-review repair 1 retains the original guarded root descriptor in the fixture
owner. Its LIFO final cleanup runs only after every owned child was reaped, so
early Fatal/timeout paths cannot bypass stage discovery. Descriptor-rooted inventory
first validates every entry: known fixture names or exact `.stage-[0-9a-f]{32}`
regular files with current UID, exact 0600 and one link. Unknown/unsafe entries
refuse cleanup unchanged. Safe stages are recorded, their identities rechecked,
and removed only by this guarded helper; no recursive deletion occurs. Explicit
crash recovery uses the same helper.

The fake config resolver now compares only targetId/runtimeId/protocolId/format/
revision after configRef lookup; profile ID is not part of that binding. The
post-flock regression now acquires a real flock, replaces the named inode, and
checks the guard deterministically. This qualifies the guard helper only; runtime
instrumentation does not independently prove `acquire()` calls it after flock.
Sol high source review must verify the actual post-acquisition ordering.

Source-review repair 2 changes only teardown: `TestJSONGuards/rootmode` uses
`Fchmod` on its original held fixture-root descriptor to restore 0700 **after**
the unsafe rejection and unchanged-state assertions. This is explicit fixture
creator cleanup, never backend permission repair. `newLab` final cleanup now
reports the fixed refusal code, closes its original root descriptor, and returns

The entire refused fixture is preserved. Other deliberately unsafe fixture names
are creator-recorded; stage-mode/symlink/hardlink/unrelated regression entries are
