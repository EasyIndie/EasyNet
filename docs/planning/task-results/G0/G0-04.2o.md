Every new operation requires nonnull ownedRef and accepted Vault.ready. Unlock

actual SecKeychainUnlock status. Separate is_unlocked clears its flag first,
checks SecKeychainGetStatus status and observes kSecUnlockStateStatus. No inferred

kSecMatchSearchList one-element array [ownedRef]. Synthetic fixed generic-password
service easynet.fixture.vault/account synthetic; no personal/default item lookup.

setting. Query/dictionary/data/array allocations checked and native status returned.

Read clears equal/dataReturned flags before validating inputs and readiness;
requests ReturnData/MatchLimitOne. Nonnull returned CF object marks dataReturned
conservatively even on native failure. Success requires CFData type, valid length
and pointer before in-memory comparison. Every returned reference releases on
native failure, unexpected type, comparison mismatch or success. No byte export,
password/secret/path logging. Update/add release all intermediate references.

vault_unchanged now clears its flag first and revokes readiness on parameter,
metadata-read error or changed ordered metadata. Later equality never restores
revoked readiness; only initial accepted creation can set ready. Thereafter only
metadata inspection/reference release remain allowed. No preferences restoration,
SecKeychainDelete, default/search-list changes, lock API or CRUD runner added.
