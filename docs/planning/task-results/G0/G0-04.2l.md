## Implementation and API

Added output.go (44 lines) and output_test.go (108 lines): 152 authored gofmt
lines. Internal zero-value `boundedOutput` provides mutex-protected
`Write([]byte) (int, error)`, `Bytes() []byte` and `Overflowed() bool`.
`outputLimit = 4096`; fixed exported sentinel `ErrOutputLimit`.
Root directed synchronized Overflowed to permit later execution adapter error
precedence without reading internal state unsafely. No close callback or SSH
execution is implemented by this writer.

One writer is intended to receive both stdout and stderr, so the cap is on their
combined bytes. Exactly 4096 is accepted, including a zero-length write at that
boundary. A crossing write accepts only the remaining prefix, reports its proper
partial count and ErrOutputLimit, and marks persistent overflow. Once overflowed,
all writes (including empty writes) return zero and the sentinel. Stored bytes
never exceed 4096. Bytes copies the retained data under the mutex; input and
returned-snapshot mutations cannot overwrite it. Overflowed reads under the
same mutex.

## Actual behavior

- Zero, exact 4096, single 4097 and 4090 + 10 boundary-straddling cases passed.
  The straddling write reports 6 accepted bytes and ErrOutputLimit; all later
  writes reject. Overflow snapshots match each expected state.
- Mutating original input and each returned snapshot leaves retained bytes intact.
- Two concurrent stdout/stderr-like streams each attempt 24 128-byte writes into
  the same writer while a third goroutine repeatedly obtains/mutates copied
  snapshots. Accepted counts sum to exactly 4096; snapshots never exceed the
  limit or overwrite retained data. Excess writes report only the limit sentinel,
  and persistent overflow is checked after both streams join. Race detector passed.
