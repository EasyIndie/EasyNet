## Implementation and fixture API

Dial now hooks the owned raw connection with context.AfterFunc during SSH setup.
Cancellation closes the socket; before either success or failure return, cleanup
stops or joins the callback. A cancelled setup normalizes its local I/O error to
ctx.Err, closes any resulting client and waits for its transport. No persistent
watcher is retained on the returned caller-owned client. Existing absolute I/O
deadline and supplied-host-trust policy remain intact.

Fixture adds immutable-before-worker `BlockReached() <-chan struct{}` plus
mutex-protected `PendingBlocks() int`. Entering fixture.block increments pending
state then closes the phase channel once. Client cancellation leaves that handler
pending; only Fixture.Close's owned done channel releases it, decrements pending
state and joins the worker. Accepted command still records before exec ack.
Observation channels/counters are independent test signals, not trusted receipts.

203 added authored gofmt lines. Root binding permits this narrow precision

  identification in an owned partial-handshake server, or AuthReached in the
  trusted real SSH public-key negotiation fixture. Both Dial calls return
  context.Canceled in under one second after cancel; no client escapes. Joined
  fixture snapshots show zero exec/commands, zero auth during handshake and
  positive auth callback in authentication negotiation. No sleeps establish phase.
- Run executes fixture.block under an exclusive owned client. BlockReached proves server handler entry after the reply attempt. The test
  separately waits for an internal signal emitted only after session.Start
  returns nil, proving client receipt of the exec acknowledgement; only then
  live cancel fires. Run returns context.Canceled, unknown, OwnerRetained=true and the
  original fixture-cancel-1 operation ID within one second. Exactly one exec
  attempt and accepted command proves no retry.
- An earlier Run context deadline of 100 ms after Dial produces the same unknown
  retained-owner binding, with context.DeadlineExceeded and one dispatched exec.
  Both cases independently observe PendingBlocks=1 after Run/client cleanup.
  Checked Fixture.Close alone releases it; PendingBlocks then equals zero.
