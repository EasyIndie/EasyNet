## 二、安全性

### 2.1 已生效的加固（实测）

| 项 | 实测值 |
|---|---|
| Shadowsocks 密钥 | ✅ 不在命令行；`config.json` `640 root:nogroup` |
| SS 进程能力集 | ✅ `CapBnd=0000000000000000`（零能力） |
| systemd 沙箱 | ✅ xray / hysteria / shadowsocks 均 `ProtectSystem=strict`、`ProtectHome=yes`、`RestrictNamespaces=yes` |
| fail2ban | ✅ sshd jail active |
| TLS（Edge 443） | ✅ TLS 1.2 + 1.3（**1.0/1.1 被拒**；1.2 是刻意保留以兼容旧客户端，见下轮审计纠错）；Let's Encrypt 证书链校验通过 |
| 安全响应头 | ✅ HSTS `max-age=63072000; includeSubDomains`、`nosniff`、`X-Frame-Options: DENY` |
| 敏感文件权限 | ⚠️ 协议配置与 metadata 均 `600/640`，但**状态目录 `/var/lib/easynet` 下的订阅路径前缀（及生成的路由文件）为 644 world-readable** —— 见第三轮审计 N1（已在该轮修复） |

### 2.2 本轮发现并修复

| 级别 | 问题 | 修复 |
|:--:|---|---|
| 🔴 **功能回退** | 客户端 `easynet-singbox-update.service` 用 `DynamicUser=yes` + `ProtectSystem=full`，**既读不到 600 的 `/etc/easynet/singbox-client.env`（Permission denied），也写不了 `/etc`** → **每日自动更新订阅一直失败**，客户端无法随服务端变化自动更新 | 更新服务改为以 root 运行 + `ProtectSystem=strict` + `ReadWritePaths=/etc/easynet /etc/sing-box`；实测 `systemctl start` 成功、规则集本地化、配置更新并重启客户端 |
| 🟠 **误封风险** | fail2ban 使用 `mode = aggressive`，其 `ddos`/`extra` 规则会匹配「连接被关闭」等正常事件，**容易误封自己** | 改为默认 `normal`；并把**部署时 SSH 会话的来源 IP 自动写入 `ignoreip`**（并支持 `EASYNET_FAIL2BAN_IGNORE_IP` 追加） |

### 2.3 遗留项（非阻塞）

| 优先级 | 问题 | 说明 / 建议 |
|:--:|---|---|
| 🔴 P0 | SSH `PermitRootLogin yes` + `PasswordAuthentication yes` | 仍未改（需显式决策）；方案与锁死分析见 `security-audit.md` 第六节。fail2ban 已把爆破成本抬高 |
| 🟠 P1 | 订阅直连路径默认开启（`/sub` 无认证） | 建议默认关闭；「稳定订阅 URL」可通过 `.env` 固定 `EASYNET_SUBSCRIPTION_PATH_PREFIX` 解决 |
| 🟡 P3 | 客户端 `mixed` 模式监听 `0.0.0.0:7890` | 设计上用于局域网共享；在公网设备上会成为开放代理（本 VPS 被 UFW 挡住）。建议默认 `127.0.0.1` + 需要共享时显式开启 |

## 三、稳定性

| 项 | 结果 |
|---|---|
| **配置幂等性** | ✅ 重跑部署后 4 个协议的配置文件 **md5 完全一致**（UUID/私钥/PSK/AWG 参数全部保留） |
| Xiray 配置未变化时跳过重启 | ✅ `Reality 配置未变化，跳过重启` |

| 内存占用（RSS） | ✅ xray 24MB、hysteria 20MB、ssserver 8MB、nginx 10MB（服务端合计 ≈ 62MB） |
| 开机自启 | ✅ 全部 `enabled` |
| 服务崩溃自恢复 | ✅ `Restart=on-failure`（xray/hysteria/ss） |
| 重部署后连通性 | ✅ 保持 204 |

**改进建议（P2）**：把 Xray 已有的「渲染到临时文件 → 比对 → 不变则跳过重启」模式推广到
hysteria2 / shadowsocks / awg-quick；nginx 改用 `reload` 而非 `restart`。这样重部署可以做到
**对在线客户端零中断**。

## 四、访问速度

测量方式：在 VPS 上以 sing-box 客户端逐节点拉取 30MB（Cloudflare 测速端点），取 `speed_download`。
**注意**：客户端与服务端同机（环回），因此数值主要反映**协议自身开销 + 本机 CPU**，不代表真实
「端到端」带宽；可用于**协议间横向对比**。

| 路径 | 连接耗时 | 首字节 | 吞吐 |
|---|---:|---:|---:|
| 直连（无代理基线） | 2.6 ms | 74 ms | **1506 Mbps** |
| Shadowsocks 2022 | 0.23 ms | 97 ms | **781 Mbps** |
| Xray+Reality (TCP+vision) | 0.42 ms | 69 ms | **349 Mbps** |
| Hysteria2 (QUIC+salamander) | 0.29 ms | 127 ms | **219 Mbps** |

**解读**：SS2022 最轻（纯 AEAD，无 TLS 握手/记录层）；Reality 因 TLS+vision 约为其 45%；
Hysteria2 最低，因其为**用户态 QUIC + salamander 混淆**，在本机 CPU 上开销最大（小规格 VPS 上
QUIC 的 CPU 成本是主要瓶颈）。三者均远超实际代理使用所需，**吞吐不是当前瓶颈**。

## 七、结论

- 重置后全新部署：**无功能回退、无流程锁死**，四种协议与三类订阅均正常。
- 本轮修复 2 个真实缺陷（客户端自动更新被沙箱破坏、fail2ban 误封风险）。
- 主要遗留：SSH 密码登录（需决策）、订阅直连路径默认值（需决策）、**重部署时非 Xray 服务无条件重启**（建议 P2 修复）。
- 性能：以本机环回测量，SS2022 > Reality > Hysteria2，均无瓶颈；真实带宽取决于 VPS 出口与线路。
